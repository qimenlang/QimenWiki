# OSG学习总结

### 一、OSG核心概念

| OSG术语                 | 其他引擎概念             | 核心作用                                                     |
| ----------------------- | ------------------------ | ------------------------------------------------------------ |
| osg::Node（节点）       | GameObject               | 场景图的基石，所有可以放入场景图的东西都是node；子节点可继承父节点属性； |
| osg::Group（组节点）    | 父节点、容器             | 一种特殊的Node,可以拥有多个子节点。是构建场景层次的主要工具； |
| osg::Geode(几何节点)    | 带有MeshRenderer的Object | 继承自group，但只可挂载**可绘制体 Drawable**                 |
| osg::Drawable(可绘制体) | Mesh组件                 | 包含用于渲染的几何数据，类似组件，继承自node,被Geode持有；   |
| osg::stateSet(状态集)   | Material / 渲染属性      | 附着在Node或*Drawable*上，定义渲染状态，定义材质纹理着色器等； |

### 二、OSG各概念之间关系梳理

1. 场景图（Scene Graph）:由osg::node构成的树
   - 优点：
     - 从属关系：树状结构自然表达物体之间的从属关系
     - 状态继承：子节点可以继承父节点的渲染状态等；
     - 高效剔除：高效遍历树状结构，判断整颗子树是否需要剔除；
     - 细节层次：根据距离自动判断、切换物体各LOD;
2. 节点（Node）:场景图中所有元素的基类，提供遍历的入口；
   - 最重要的两个派生类：
     - osg::group : 容器节点
     - osg::geode ：可以持有osg::drawable的几何体叶子结点
3. 可绘制体（Drawbable）
   - 真正包含可绘制几何信息的对象
   - 本身不是Node，只可被附着到osg::geode

### 三、OSG核心优势

1. 适合静态场景的渲染；

2. node继承架构带来的Node自带BVH场景剔除以及LOD管理；

3. 动态分页调度（Paged LOD）：是OSG处理**超大规模场景**（如全球地形）的核心机制，解决了100GB的地形数据，在8GB内存的机器上流畅浏览。

   ```c++
   osg::ref_ptr<osg::PagedLOD> terrainTile = new osg::PagedLOD();
   terrainTile->setFileName(0, "high_detail.osgb");      // 立即加载
   terrainTile->setFileName(1, "medium_detail.ive");     // 需要时异步加载
   terrainTile->setRange(0, 0, 10000);                   // 高细节范围
   terrainTile->setRange(1, 10000, 50000);               // 中等细节范围
   // OSG的DatabasePager在后台线程：
   // 1. 预测摄像机移动
   // 2. 预加载即将可见的瓦片
   // 3. 卸载远离的瓦片
   ```


### 四、渲染顺序

1. 渲染顺序

   ```glsl
   Frame start
   │
   ├── PRE_RENDER Cameras   
   │
   ├── MAIN CAMERA
   │   ├── Opaque
   │   ├── TransparentBin（深度排序 + blend）
   │
   ├── POST_RENDER Cameras  
   │
   └── Frame end
   ```

2.  **同一个 RenderOrder + 同一个 orderNum** 下：**Camera 的执行顺序，等于它们被加入渲染图（SceneGraph）时的遍历顺序**
### 四、渲染机制

1. 深度测试默认关闭、深度写入默认打开、深度缓冲默认全为最远值1；
2. 在 OSG 中，状态设置是 **按需增量** 的，而不是每帧无条件重置所有状态。OSG 渲染时，会遍历场景图，对比当前节点与上一个节点使用的 `StateSet`，**只改变发生变化的属性**。这种设计是为了最小化 OpenGL 状态切换次数，提升性能。

### 五、多线程模式

| 模式                         | 剔除 (Cull) 线程模型         | 绘制 (Draw) 线程模型 | 适用场景                                                     |
| :--------------------------- | :--------------------------- | :------------------- | :----------------------------------------------------------- |
| **SingleThreaded**           | 主线程串行                   | 主线程串行           | 调试、简单场景、兼容性要求高时                               |
| **CullDrawThreadPerContext** | 每个上下文 1 个线程 (串行)   | 与剔除共用线程       | 多 GPU 工作站（多屏独立显卡）                                |
| **DrawThreadPerContext**     | 主线程（并行处理多个上下文） | 每个上下文 1 个线程  | **单 GPU 高性能场景**，主频高的 CPU                          |
| **CullThreadPerCamera...**   | 每个相机 1 个线程            | 每个上下文 1 个线程  | **多相机复杂场景**（如多视口、阴影图、反射），CPU 核心数多（>4核） |
| **AutomaticSelection**       | 自动                         | 自动                 | 不确定配置，希望 OSG 自行决定                                |

### 六、场景状态管理模式

这两个术语描述的是**图形 API 或框架与应用程序之间的交互方式**，即**场景数据如何被管理和提交给 GPU**

1. OSG = 保留模式（Retained Mode）:应用程序构建一个**持久化的场景数据结构**（如场景图），框架会“记住”这个场景。每一帧，框架自动遍历该结构，将几何体、状态、变换等转化为底层的图形 API 调用。

    “我把场景交给你，你帮我一直管理和渲染”

   - 你创建节点（Node / Geode / Camera）
   - 建立**场景树（Scene Graph）**
   - 把数据“存”在引擎里，持久化存在
   - 之后每一帧：
     - OSG 自动遍历
     - 自动裁剪（culling）
     - 自动排序
     - 自动渲染

    关键词：**数据被“保留”在系统中**

2. ImGui = 即时模式（Immediate Mode）:应用程序在每一帧**直接发出绘制命令**，不保留场景结构。框架只提供绘制基本图元的函数，开发者负责每帧重新提交所有需要渲染的内容。

    “每一帧你都重新告诉我 UI 长什么样”

   ```
   ImGui::Begin("Panel");
   ImGui::SliderFloat("roughness", &r, 0, 1);
   ImGui::End();
   ```

   - 不存 UI 树（你不维护 Button 对象）
   - 每帧重新“画一遍 UI”，不画就消失
   - UI 状态由你自己控制（变量）
   - **重要优势：**
     - **极简：逻辑与渲染在同一地方，调试极其直观**
     - **无状态**：不需要维护控件对象树，无状态与数据不一致问题

   关键词：**UI 不被保留，每帧重建**
