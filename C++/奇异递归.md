## **奇异递归模板模式（Curiously Recurring Template Pattern，简称 CRTP）**

**原理**：让一个类继承以自身作为模板参数的模板基类，实现静态多态；

**目的**：实现编译时多态，避免虚函数开销，并实现各种“混入”的通用功能（克隆、计数、操作符重载等）；

**适用场景**：对性能要求高的多态、为类族添加通用功能、运算符自动化等。

**基本形态**： class Derived : public Base<Derived>

```c++
template <typename Derived>
class Base {
    // 基类中可以使用Derived类型
};

class Derived : public Base<Derived> {
    // 派生类
};

```

**实现方式**：**基类中通过static_cast安全地将this指针转换为派生类指针；**因为 `this` 实际上指向的是一个 `Derived` 对象。然后它调用 `Derived::implementation()`。整个过程在编译期就确定了函数调用，没有虚函数表的查找开销。

#### 具体示例：

```c++
template <typename Derived>
class Animal {
public:
    void speak() const {
        static_cast<const Derived*>(this)->speak();
    }
};

class Dog : public Animal<Dog> {
public:
    void speak() const {
        std::cout << "Woof!" << std::endl;
    }
};

class Cat : public Animal<Cat> {
public:
    void speak() const {
        std::cout << "Meow!" << std::endl;
    }
};

template <typename T>
void letAnimalSpeak(const Animal<T>& animal) {
    animal.speak();
}

int main() {
    Dog dog;
    Cat cat;
    letAnimalSpeak(dog); // 输出：Woof!
    letAnimalSpeak(cat); // 输出：Meow!
    return 0;
}

```



#### 静态多态&动态多态

1. 静态多态：编译期多态
   - 可以避免动态多态的虚函数开销；
   - 没有虚函表的内存开销；
2. 动态多态：运行期多态

#### CRTP 的注意事项和局限性

1. **非多态析构**：CRTP 基类通常没有虚析构函数。这意味着你不应该通过基类指针（如 `Base<Derived>*`）来删除派生类对象，这会导致未定义行为。CRTP 设计用于静态多态，而不是动态多态。

2. **“菱形继承”问题**：如果一个类试图通过 CRTP 从同一个基类模板实例化两次，会导致编译错误，因为同一个类在继承体系中会出现两次。

   cpp

   ```
   // 错误示例
   class Derived : public Base<Derived>, public Base<Derived> { // 非法
   };
   ```

   

3. **代码膨胀**：模板会为每种不同的派生类生成一份基类代码，可能导致编译后的二进制文件变大。
