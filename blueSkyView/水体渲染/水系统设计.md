# 现代实时图形引擎 Water System 技术架构总结（学习路线与模块划分）

## 一、Water System 的定位

水体系统（Water System）并不是一个单独的 Shader 或渲染 Pass，而是图形引擎中的一个大型子系统。它需要同时解决海洋、河流、湖泊等不同类型水体的模拟、渲染以及与场景中其他对象的交互。

一个完整的 Water System 通常横跨以下几个方向：

- 水体模拟（Simulation）
- 水体渲染（Rendering）
- 水体交互（Interaction）
- GPU计算（Compute）
- 特效系统（VFX）
- 性能优化（Optimization）
- 调试工具（Debug）

因此，它更接近 Terrain、Particle、Animation 这样的一级子系统，而不是一个简单的 Shader。

------

# 二、Water System 总体架构

建议将整个系统划分为以下几个模块：

```
Water System
│
├── Water Simulation          // 水面模拟
├── Water Rendering           // 水体渲染
├── Water Interaction         // 场景交互
├── Water Effects             // 泡沫、水雾、水滴等特效
├── Water Physics             // 浮力、流速等物理接口
├── Water Resource            // RenderTarget、Buffer管理
├── Water LOD                 // 大场景LOD管理
└── Water Debug               // 调试与可视化
```

每个模块职责应尽可能独立，避免所有逻辑集中在一个 Water.cpp 中。

------

# 三、Water Simulation（水体模拟）

这是整个系统的核心。

它负责计算水面随时间如何变化，并输出高度、法线、速度等数据。

建议进一步划分为多个模拟模块。

## 1、背景海浪（Background Ocean）

用于模拟大尺度海洋起伏。

常见算法包括：

- Gerstner Wave
- FFT Ocean
- Phillips Spectrum
- JONSWAP Spectrum

主要特点：

- 计算大范围海浪
- 周期稳定
- 性能较高
- 不适合局部交互

输出：

- Height
- Normal
- Horizontal Displacement

------

## 2、局部水波（Interactive Ripple）

负责角色踩水、船尾波、直升机下洗等局部扰动。

建议采用：

Height Field + 二维波动方程

主要维护：

- Height Texture
- Previous Height
- Velocity Field

特点：

- 波纹可传播
- 可衰减
- 可叠加
- 可产生干涉

典型应用：

- 人物踩水
- 爆炸冲击波
- 船尾波
- Rotor Downwash

------

## 3、Velocity Field（速度场）

现代水体越来越依赖速度场。

速度场用于表示：

```
每个位置
↓

水流方向

+

流速大小
```

Velocity Field 可以驱动：

- 泡沫生成
- 水滴运动
- Spray方向
- Flow Map
- 漂浮物

建议维护：

```
VelocityX
VelocityY
```

必要时加入：

```
Vertical Velocity
```

------

## 4、Flow Simulation（流场模拟）

适用于：

- 河流
- 水渠
- 洪水
- 下洗

一般维护：

```
Velocity

Density

Pressure
```

如果进一步扩展，可以实现：

二维Euler Fluid。

------

# 四、Water Rendering（水体渲染）

Simulation 负责产生数据。

Rendering 负责表现数据。

通常包括以下模块。

## 1、PBR Water Material

包括：

- Base Color
- Roughness
- Metallic（通常固定）
- Normal

支持：

- BRDF
- IBL

------

## 2、Reflection（反射）

包括：

- Screen Space Reflection（SSR）
- Planar Reflection
- Reflection Probe
- Cubemap Reflection

不同距离采用不同反射方案。

------

## 3、Refraction（折射）

模拟：

水下景物折射。

通常包括：

- Scene Color采样
- 折射偏移
- Depth修正

------

## 4、Fresnel

控制：

不同观察角度下：

反射与折射比例。

属于水材质最重要部分。

------

## 5、Water Absorption

采用：

Beer-Lambert Law

模拟：

水越深颜色越深。

主要影响：

- 河流
- 湖泊
- 海洋

------

## 6、Caustics（焦散）

模拟：

阳光穿过水面产生的光斑。

实现方式：

- Animated Texture
- Projector
- Ray March

------

## 7、Underwater Rendering

包括：

- Water Fog
- Color Shift
- Light Scattering
- God Ray

------

# 五、Water Effects（水体特效）

主要负责表现细节。

包括：

## Foam（泡沫）

建议来源：

- Velocity
- Curvature
- Slope
- Compression

不要完全依赖Noise。

------

## Spray（水花）

通常：

GPU Particle。

来源：

- 船尾
- 爆炸
- 下洗
- 跌落

------

## Mist（水雾）

通常：

GPU Particle

或者：

Grid Fluid

特点：

具有速度场。

------

## Droplet（水滴）

生命周期：

较短。

通常：

受Velocity驱动。

------

# 六、Water Interaction（场景交互）

这是现代Water最大的区别。

建议统一管理所有交互源。

例如：

```
Character

Boat

Aircraft

Explosion

Rain

Projectile
```

每一种交互：

向Simulation写入：

```
Impulse

Velocity

Force

Pressure
```

而不是：

直接修改Shader。

------

提供给游戏逻辑。

包括：

## 浮力

根据：

Water Height

计算：

物体浮力。

------

## 水流

提供：

Velocity查询。

供：

船只

漂浮物

AI

使用。

------

## 水深查询

提供：

Depth Sampling。

用于：

角色

船只

物理。

------

# 八、Water Resource（资源管理）

主要负责：

GPU资源。

例如：

维护：

```
Height RT

Velocity RT

Foam RT

Normal RT

Flow RT
```

Compute Shader：

不断更新。

Rendering：

读取。

------

# 九、Water LOD

适用于：

超大场景。

建议划分：

远景：

FFT

中景：

Gerstner

近景：

Height Field

超近景：

Particle

LOD之间：

渐变。

避免跳变。

# 十、Water Debug

建议从项目一开始就建设。

包括：

可视化：

Height

Normal

Velocity

Foam

Flow

Particle Density

Pressure

这样调试Simulation会非常方便。

# 十一、推荐学习路线

建议按以下顺序学习，而不是同时研究所有内容。

第一阶段：水体渲染基础

学习内容：

- PBR
- Fresnel
- Reflection
- Refraction

目标：

完成一个静态水材质。

------

第二阶段：背景海浪

学习：

- Gerstner
- FFT

目标：

完成基础海洋。

------

第三阶段：Height Field

学习：

二维波动方程。

目标：

实现：

局部Ripple。

------

第四阶段：Velocity Field

加入：

速度纹理。

目标：

统一驱动：

Ripple

Foam

Particle。

------

第五阶段：Foam

根据：

Velocity

Curvature

Slope

生成泡沫。

------

第六阶段：Particle

实现：

GPU Spray

Mist

Droplet。

------

第七阶段：Interaction

支持：

船

角色

飞机

爆炸。

统一写入Simulation。

------

第八阶段：大型系统

加入：

LOD

Streaming

Buoyancy

River

Waterfall

调试工具。

最终形成完整Water Framework。

------

# 十二、建议最终形成的项目结构

```
Engine
└── Water
    ├── Simulation
    │     ├── OceanFFT
    │     ├── Gerstner
    │     ├── HeightField
    │     ├── VelocityField
    │     └── FlowSimulation
    │
    ├── Rendering
    │     ├── Material
    │     ├── Reflection
    │     ├── Refraction
    │     ├── Underwater
    │     └── Caustics
    │
    ├── Effects
    │     ├── Foam
    │     ├── Spray
    │     ├── Mist
    │     └── Droplet
    │
    ├── Interaction
    │     ├── Boat
    │     ├── Character
    │     ├── Rotor
    │     ├── Rain
    │     └── Explosion
    │
    ├── Physics
    │     ├── Buoyancy
    │     └── WaterQuery
    │
    ├── Resource
    │
    ├── LOD
    │
    └── Debug
```

整个 Water System 的最终目标，并不是实现某一种具体算法，而是建立一个可扩展的实时水体框架，使海洋、河流、湖泊、船尾波、直升机下洗、水花、水雾、泡沫等各种效果共享统一的数据结构和交互机制。这种架构不仅适用于水体，还可以扩展到雪地、沙地、泥地、烟雾等其他基于场的模拟系统，是现代实时图形引擎的重要基础设施之一。
