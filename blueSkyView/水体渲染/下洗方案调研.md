## 整体方案：

1. 基础海面（Background Ocean）,范围(10m,1km），提供真实海浪背景

   - FFT Ocean
   - Gerstner cluster

2. Rotor Pressure area ,旋翼压力区，一个圆形压力场：

   - 模型：P(r) = exp(-r² / R²)
   - 作用：压低水面，产生径向向外水流

3. Rotor DownWash : 下洗气流

   - 作用：中心压低、外围波纹扩散，海面中心凹陷
   - 模型：H_downwash = -A * exp(-r²/R²)

4. Rotor Vortex Ring : 旋翼涡环

   - 作用：产生换装涡流
   - 模型：sin(kr - ωt) * exp(-r²)

5. Kelvin Wake：旋翼尾流

   - 作用：形成类似船尾波纹

## Triton 学习总结

1. ellipsoid格子锯齿问题排查

   - V+trit_camera_pos重建世界坐标会导致float32精度损失
     - V是相对相机的偏移，不是世界坐标
     - 在WGS84坐标下两个ECEF坐标相减时，float32在大数值(距离地心10000千米？，为什么大数值会精度损失？)下有效精度只有0.5-1.0m。导致UV呈现格子状。在Flat坐标下，坐标在0-500m量级，不会有该问题；
   - 使用trit_basis局部坐标，并在CPU端传入高精度相机相对坐标

2. 什么是trit_east、trit_north

3. trit_basis、trit_invBasis

   - 局部坐标系：X、Y：海面上的水平方向（贴图、FFT、尾迹坡度），Z：垂直海面，向上；
   - trit_basis : 转换世界坐标系到局部坐标系，**basis:基准坐标系、海洋切平面局部系**；
   - trit_invBasis : 转换局部坐标系到世界坐标系；

4. `V` 是 相对相机的坐标（camera-relative / eye-relative），不是绝对世界坐标。

   Triton 故意把 modelview 的平移清零，相机位置单独用 `trit_cameraPos` 传入，注释写得很清楚：

   ```c++
   // To avoid precision issues, the translation component of the modelview matrix
   // is zeroed out, and the camera position passed in via cameraPos
   ```

   因此：

   | 变量             | 含义                                                     |
   | :--------------- | :------------------------------------------------------- |
   | `localPos` / `V` | 海面点 相对相机 的位置                                   |
   | `worldPos`       | 绝对坐标（flat 下是应用世界系；ellipsoid 下是 地心坐标） |

   关系始终是：

   ```c++
   worldPos = localPos + trit_cameraPos   // 即 V + trit_cameraPos
   ```

   片段着色器需要绝对世界坐标时，会自己加回去：

   ```c++
   vec3 worldPos = V + trit_cameraPos;
   ```

   为什么用相机相对坐标？
   地球尺度下，绝对坐标数值很大（百万米级），GPU 单精度会丢精度。把原点挪到相机附近，`V` 保持在几百～几千米量级，顶点/片段计算更稳定。
