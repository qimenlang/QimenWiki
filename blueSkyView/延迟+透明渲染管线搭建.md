# Transparent Pass 合成机制

混合方式：

- 画家算法排序：根据到相机距离排序，从后往前绘制，**drawable**级别；有自交叉、循环遮挡问题；
- 深度剥离：通过多次渲染场景，每次剥离出当前最浅的深度层，从而获得多个深度层上的片段并按层混合，能得到比简单排序更准确的结果，但性能开销随层数增加而增大。
- OIT：
  - Abuffer : 收集所有片段，像素内排序，精确混合；性能差；
  - Weighted Blended OIT:不排序、不存储所有 fragment、用加权累加代替真实混合运算，不完全物理正确；

整体渲染流程：

- SceneGroup→ Scene Pass → 输出 Gbuffer(CompositColor + Normal+ SceneLevelAlpha...)
- TransGroup→ TSP Pass → 渲染所有半透明物体为半透明层(TSPMixColor)
- TransGroup→ TSP Alpha Pass → 渲染所有半透明物体的TSPLevelAlpha  
- CompositColor+SceneLevelAlpha+TSPMixColor+TSPLevelAlpha →  Levels Pass→ 四层颜色合成
  - 替代方案：CompositColor+TSPMixColor+SceneLevelAlpha ，只关心不透明的雾效


TransparentPass流程：

- 输入：TransGroup
- StateSet设置：关深度写入、开深度测试、开混合、混合函数：glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)、Drawable级别渲染（TransparentBIN）
- 输出：TSPMixColor

- 非物理真实，与画家算法不一致，视觉可接受；

- movingmodel stateset复用+MRT导致的Transparent Alpha Pass 浪费带宽
  - 场景图设计问题：是否应该复用 StateSet；
  
  - TSP Alpha Pass 存在的原因：多层半透物体的TSPLevelAlpha只保留最前面一层
  
  - 待验证的重构方案：取消TSP Alpha Pass ，在 TSP Pass中直接输出 TSPLevelAlpha，指定关闭对TSPLevelAlpha 的混合 
  
    ```c++
    class PerTargetBlend : public osg::StateAttribute
    {
    public:
        PerTargetBlend(unsigned index);
        virtual void apply(osg::State& state) const override
        {
            osg::GLExtensions* ext = state.get<GLExtensions>();
            ext->glEnablei(GL_BLEND, 0);
            ext->glBlendFuncSeparatei(0,
                    GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA,
                    GL_ONE, GL_ONE_MINUS_SRC_ALPHA);
            for (int i = 1; i < 4; ++i)
                    ext->glDisablei(GL_BLEND, i);
        }
    private:
        unsigned _blendIndex;
    };
    ```
