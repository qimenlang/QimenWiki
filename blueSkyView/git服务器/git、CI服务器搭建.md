#### 存在问题：

1. gitlab ce需要有哪些依赖：自动解析，不需要管

2. 团队成员如何配置证书、身份等

3. 内外两个团队协同问题

   - 在内网搭建，外协团队定期更新的代码，与内部团队平时开发的代码，在合入时，会有较多冲突；

   - 外协团队不跑CI\渲染回归，合入其代码，可能引入bug;

   - 外协团队拿不到内部版本，时间长了，两边分支独立演化；每次合入时，需要按内部功能标准做重复解冲突工作；

   - ##### 解决方案

     1. 划分所有权：哪些目录/模块归外协，哪些归内网，尽量不交叉改
     2. 小步同步：缩短导入周期（周/双周），不要季度大爆炸
     3. 专用集成分支：不在 `main` 上直接和外协代码硬 merge
     4. 导入前可编译、导入后必跑 CI（含渲染回归）
     5. 差异可追踪：每次导入有记录：来源版本、变更说明、冲突处理人
     6. 是否可以在受控外网搭建git服务器
        - 受控外网是否方便内外团队同步；
        - 受控外网是否方便使用AI；
        - 受控外网是否可以访问内网（内网存储完全保密的模块，内网编译出 lib，受控外网/集成机链接）;
        - 受控外网的保密性、安全性如何、新引擎项目达到了必须做物理隔离的密级；
