# 离线安装：依赖从哪里来？`dpkg -i` 做什么？

你的疑问很对：官方文档在「安装依赖」那一步写得很简略，**没有单独列依赖清单**——因为依赖是由 **apt 自动解析** 的，不是手填一张列表。

官方离线指南：[Install an offline GitLab Self-Managed instance](https://docs.gitlab.com/topics/offline/quick_start_guide/)

---

## 依赖 .deb 从哪里来？

答案：**在同一版本 Ubuntu 的联网机器上，用 `apt` 下载 GitLab 包时，apt 会自动把全部依赖一起下到缓存目录。**

文档「Download the GitLab package」里其实已经写了（只是容易漏看）：

```bash
# 1. 添加 GitLab 官方仓库
curl --silent "https://packages.gitlab.com/install/repositories/gitlab/gitlab-ce/script.deb.sh" | sudo bash

# 2. 只下载、不安装 —— 关键命令
sudo apt-get install --download-only gitlab-ce

# 3. 所有 .deb 都在这个目录里（gitlab-ce + 全部依赖）
sudo cp /var/cache/apt/archives/*.deb /path/to/usb/
```

`--download-only` 的作用：

- apt 根据 `gitlab-ce` 的元数据**递归解析**所有依赖
- 把 `gitlab-ce` 和所有依赖的 `.deb` 下载到 `/var/cache/apt/archives/`
- **不在本机安装**

所以你**不需要**自己查「到底要哪 20 个包」——apt 会帮你算出来。

## 完整流程（Ubuntu 离线装 GitLab CE）

```
联网 Ubuntu（版本与离线机一致，如都是 22.04）
    │
    ├─ 添加 gitlab-ce 仓库
    ├─ apt-get install --download-only gitlab-ce
    └─ 拷贝 /var/cache/apt/archives/*.deb → U 盘
                │
                ▼
离线 Ubuntu 服务器
    │
    ├─ 1. 先装依赖（不含 gitlab-ce 本体）
    ├─ 2. 再装 gitlab-ce
    └─ 3. gitlab-ctl reconfigure
```

### 联网机器（下载）

```bash
# 假设两台都是 Ubuntu 22.04 amd64
curl --silent "https://packages.gitlab.com/install/repositories/gitlab/gitlab-ce/script.deb.sh" | sudo bash

sudo apt-get update
sudo apt-get install --download-only gitlab-ce

# 查看下载了哪些包
ls -lh /var/cache/apt/archives/*.deb

# 拷到 U 盘
sudo cp /var/cache/apt/archives/*.deb /media/usb/
```

常见会包含（因版本而异，以实际下载为准）：

- `gitlab-ce_<version>_amd64.deb`（主包）
- 以及 openssh-server、curl、ca-certificates、logrotate 等 apt 解析出的依赖

### 离线机器（安装）

```bash
cd /media/usb

# 方式 A：一次性装所有包（推荐，apt 会按顺序处理）
sudo dpkg -i *.deb

# 若报依赖未满足，再执行：
sudo apt-get install -f   # 离线机上无仓库时会失败，见下方方式 B

# 指定 EXTERNAL_URL 安装 GitLab
sudo EXTERNAL_URL="http://192.168.1.100" dpkg -i gitlab-ce_*.deb

sudo gitlab-ctl reconfigure
```

**更稳妥的方式 B：先依赖、后主包**

```bash
# 先装除 gitlab-ce 以外的所有 deb
sudo dpkg -i $(ls *.deb | grep -v gitlab-ce)

# 再装 gitlab-ce
sudo EXTERNAL_URL="http://192.168.1.100" dpkg -i gitlab-ce_*.deb

sudo gitlab-ctl reconfigure
```

## `dpkg -i` 是解压还是安装？

**是安装，不是单纯解压。**

| 命令                   | 作用                                          |
| ---------------------- | --------------------------------------------- |
| `dpkg -i xxx.deb`      | 安装该 deb 包（解包 + 写文件 + 注册包数据库） |
| `dpkg -x xxx.deb dir/` | 仅解压到目录，不安装                          |
| `dpkg -I xxx.deb`      | 查看包信息，不安装                            |

`.deb` 类似 Windows 的 `.msi`：双击/一条命令完成安装。

## 文档里 `sudo cd /path/to/mount` 的问题

这是文档笔误：**`cd` 不是 dpkg 命令，不能用 sudo 这样写。** 应改为：

```bash
cd /path/to/mount    # 普通 cd 即可
sudo dpkg -i *.deb
```

## 若不用 `--download-only`，怎么查依赖？

### 方法 1：只看依赖名（不下载）

```bash
apt-cache depends gitlab-ce
```

### 方法 2：递归列出所有依赖包名

```bash
sudo apt-get install apt-rdepends
apt-rdepends gitlab-ce | grep -v "^ "
```

### 方法 3：逐个下载（繁琐，不推荐）

```bash
apt-get download $(apt-rdepends gitlab-ce | grep -v "^ ")
```

**仍推荐 `--download-only`**：版本匹配、依赖完整、最简单。

## 重要注意事项

### 1. 系统版本必须一致

| 联网下载机         | 离线安装机                  |
| ------------------ | --------------------------- |
| Ubuntu 22.04 amd64 | 必须也是 Ubuntu 22.04 amd64 |

22.04 下载的包不能装到 20.04 上。

### 2. 先添加仓库再 download-only

必须先执行 `script.deb.sh` 添加 GitLab 仓库，否则 apt 找不到 `gitlab-ce`。

### 3. CentOS/RHEL 离线做法类似

```bash
# 联网机
curl -s https://packages.gitlab.com/install/repositories/gitlab/gitlab-ce/script.rpm.sh | sudo bash
dnf download gitlab-ce --resolve --destdir=/path/to/usb

# 离线机
sudo EXTERNAL_URL="http://gitlab.local" rpm -Uvh /path/to/usb/*.rpm
```

### 4. 离线机装完后

按官方建议关闭需外网的功能：

```ruby
# /etc/gitlab/gitlab.rb
gitlab_rails['usage_ping_enabled'] = false
gitlab_rails['version_check_enabled'] = false
```

然后 `sudo gitlab-ctl reconfigure`。

## 总结

| 问题               | 答案                                                         |
| ------------------ | ------------------------------------------------------------ |
| 依赖清单在哪？     | **没有固定列表**；由 apt 根据 `gitlab-ce` 自动解析           |
| 依赖 .deb 从哪来？ | 联网机执行 `apt-get install --download-only gitlab-ce`，在 `/var/cache/apt/archives/` |
| `dpkg -i` 做什么？ | **安装** deb 包，不是只解压                                  |
| 推荐做法           | 联网机 `--download-only` → U 盘拷全部 `.deb` → 离线机 `dpkg -i` |

**一句话：不用自己找依赖列表；在相同 Ubuntu 版本的联网电脑上 `apt-get install --download-only gitlab-ce`，缓存目录里的所有 `.deb` 就是你要拷走的内容。**
