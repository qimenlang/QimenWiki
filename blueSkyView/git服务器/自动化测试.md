# 图形渲染引擎测试体系设计总结（Unit / Mock / Integration / E2E）

------

# 一、测试体系总体分层

在从 0 到 1 构建图形渲染引擎时，测试通常分为四层：

```
Unit Test（单元测试）
    ↓
Mock-based Test（基于模拟依赖的测试）
    ↓
Integration Test（集成测试）
    ↓
E2E Test（端到端测试）
```

它们的区别不在“是否有框架”，而在：

> **测试对象的系统边界逐层扩大**

------

# 二、核心概念定义

## 1. 单元测试（Unit Test）

### 定义

验证**最小功能单元是否正确**（函数 / 类 / 小模块）。

### 特点

- 粒度最小
- 逻辑隔离
- 不依赖真实GPU/IO/系统
- 关注“计算是否正确”

### 示例模块

- Vector / Matrix 数学库
- Quaternion
- ECS系统局部逻辑
- RenderGraph DAG排序逻辑
- Shader permutation生成

------

## 2. Mock Test（模拟测试）

### 定义

通过**模拟依赖（Mock对象）替代真实系统依赖**的测试方法。

### 本质

> Mock 是“隔离手段”，不是测试类型

### 关键点

- 用假 GPU / 假 IO / 假 backend
- 控制输入输出可预测
- 用于验证“调用逻辑是否正确”

### 示例（RenderGraph）

```cpp
MockGPU gpu;

graph.execute(gpu);

// 验证调用顺序
ASSERT_EQ(gpu.calls[0], "ShadowPass");
ASSERT_EQ(gpu.calls[1], "LightingPass");
```

### 使用范围

- 单元测试中（最常见）
- 集成测试中（部分场景）

------

## 3. 集成测试（Integration Test）

### 定义

验证**多个模块组合在一起能否正确协作运行**

### 特点

- 多模块真实参与运行
- 可能使用 mock GPU 或真实 GPU
- 验证“系统协作正确性”

### 典型组合

- Renderer + RenderGraph + Material + Shader
- Resource system + IO + cache
- ECS + Scene + Transform system

### 示例

```cpp
TEST(RendererIntegration, ShadowPipeline)
{
    Engine engine;
    engine.init();

    Scene scene;
    scene.addLight();
    scene.addMesh();

    Image img = engine.renderFrame().backbuffer();

    ASSERT_GT(meanBrightness(img), 0.2);
}
```

### 核心目标

- 模块之间接口正确
- pipeline流程正确
- 数据流正确

------

## 4. 端到端测试（E2E Test）

### 定义

从“用户输入”到“最终输出结果”的完整系统测试。

### 特点

- 最接近真实使用场景
- 通常使用真实GPU
- 成本高但价值最大
- 稳定性相对较低

### 示例

```cpp
TEST(E2E, LoadSceneAndRender)
{
    Engine engine;
    engine.init();

    engine.loadScene("scene.json");

    Image img = engine.captureFrame();

    compareWithGolden(img, "expected.png");
}
```

### 核心目标

- 引擎作为“产品”是否可用
- 是否满足视觉/功能预期
- 防止系统级回归

------

# 三、四者核心区别总结

| 类型             | 测试对象     | 是否mock | 是否真实GPU | 主要目标 |
| ---------------- | ------------ | -------- | ----------- | -------- |
| Unit Test        | 单函数/模块  | 可用     | 否          | 逻辑正确 |
| Mock Test        | 依赖替换方式 | 是       | 否          | 隔离验证 |
| Integration Test | 多模块系统   | 少量     | 可选        | 协作正确 |
| E2E Test         | 整个引擎     | 几乎不用 | 是          | 产品正确 |

------

# 四、关键认知（非常重要）

## 1. Mock ≠ 单元测试

Mock 是技术手段，可以用于任何测试层级。

## 2. 单元测试 ≠ 小规模测试

单元测试定义的是“测试范围”，不是是否mock。

## 3. 集成测试 ≠ 不用mock

集成测试可以部分mock GPU或IO。

## 4. E2E ≠ UI测试

在图形引擎中，E2E是“完整渲染系统验证”。

------

# 五、工程组织方式（推荐结构）

```
tests/
  unit/              # 快速逻辑验证
  integration/       # 模块组合测试
  e2e/               # 系统级测试
```

------

# 六、CI执行策略（工业实践）

```
PR提交：
    → Unit Test（必须通过）

Nightly Build：
    → Integration Test

Release Candidate：
    → E2E + Golden Image Test
```

------

# 七、各层测试关注点总结

## Unit Test关注：

- 数学正确性
- 数据结构正确性
- 纯逻辑正确性

## Integration Test关注：

- 模块协作
- pipeline流程
- 数据传递正确性

## E2E Test关注：

- 渲染结果正确性
- 系统稳定性
- 场景加载能力

------

# 八、渲染引擎推荐测试策略（实践版）

## 必须实现（核心）

- Unit Test（数学 + ECS + RenderGraph）
- Mock GPU Test（RenderGraph / backend）

## 强烈建议

- Integration Test（Renderer pipeline）

## 少量但关键

- E2E + Golden Image Regression

------

# 九、总结一句话（工程核心）

> Unit Test保证“逻辑正确”，Mock保证“依赖隔离”，Integration保证“模块协作”，E2E保证“系统可用”。
