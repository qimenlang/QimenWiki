## BUG排查

- [x] 纹理在特定视角、特定阶段渲染异常问题
- [x] color interpolator alpha通道不生效
- [ ] 运行时崩溃：opengl drawcall 问题
  - 现象：运行时不定期崩溃，粒子数增加，崩溃概率增加；
  - 复现方法：提升粒子capacity,设置为immotal，使粒子数稳步增加，几千时基本可以复现
  - 崩溃位置：void GLBuffer::render->glDrawArrays(primitive,0,drawVertexCount);
  - 结论：Intel HD 2000 驱动对 fixed-function 的 client array + glDrawArrays 路径本身不稳定；【在4090显卡很可能存在同样问题，待验证】
  - 修复方法：改用 immediate mode（`glBegin/glEnd`），逐顶点填充数据 `glTexCoord* + glColor4ub + glVertex3f`，替换glDrawArrays ；
  - 总结
    - glBegin & glEnd
      - `glBegin` 和 `glEnd` 是 OpenGL **立即模式（Immediate Mode）** 中的核心函数
      - `glBegin(GLenum mode)` 告诉 OpenGL 接下来要绘制哪种图元（点、线、三角形等）。
      - 在 `glBegin` 和 `glEnd` 之间，每调用一次 `glVertex*` 就会为该顶点绑定当前设置的**颜色、法线、纹理坐标**等状态。
      - `glEnd()` 表示当前图元的所有顶点已发送完毕，OpenGL 此时执行实际的光栅化与渲染。
    - `glEnableClientState` 是 OpenGL 1.1 引入的**客户端状态启用函数**，用于激活**顶点数组（Vertex Arrays）**功能中的特定属性通道。调用后，OpenGL 便知道在调用 `glDrawArrays` 或 `glDrawElements` 时，应该从**客户端内存（即应用程序内存）**中读取对应的属性数据，而不是从当前状态机的单值。从 OpenGL 3.0 开始，**`glEnableClientState` 和整个顶点数组机制已被废弃**，取而代之的是**顶点缓冲对象（VBO）和顶点数组对象（VAO）**
