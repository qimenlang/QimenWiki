  一、模块核心功能

  多通道同步（Multi-Channel Sync / Image Generator Sync）远不止"时间戳+帧号"那么简单，通常包含以下几层：

  1. 时钟同步层（Time Sync）

  - 主时钟分发：一台机器作为 Time Master，其他为 Slave
  - 协议选型：NTP（毫秒级）→ PTP/IEEE 1588（微秒级）→ 硬件 GPS/IRIG-B（亚微秒）
  - 时钟漂移补偿：Kalman 滤波 / PI 控制器持续校正
  - 仿真时间 vs 墙上时间：飞行仿真通常有独立的 sim time（可暂停、快进）

  2. 数据/状态同步层（State Sync）

  - 飞行动力学状态（位置、姿态、速度、操纵面）由主机计算后广播
  - 环境状态：天气、光照、云层、能见度、其他 AI 飞机
  - 事件同步：武器发射、灯光、故障注入、教官指令
  - 传输通常走 UDP 组播 + 可靠层（如 HLA/DIS/CIGI）

  3. 帧同步层（Frame Sync / Lockstep）

  - 所有通道必须渲染同一帧号 + 同一仿真时刻的画面
  - 常见模型：
    - Lockstep：所有客户端 ACK 后主机才推进（延迟高、最稳）
    - Predictive + Correction：客户端外推，收到权威状态后修正
    - Frame-locked broadcast：主机以固定 Hz 广播，客户端严格按帧号消费

  4. 显示/交换同步层（Display Sync）— 最容易被忽略

  即使前面全部完美，投影拼接墙上仍会出现撕裂/错帧，因为各显卡的 VSync 不同相位。必须解决：
  - Genlock：所有显示器/投影机的水平/垂直扫描锁到同一同步信号
  - Framelock：所有 GPU 的 buffer swap 在同一 VSync 边沿发生
  - 硬件：NVIDIA Quadro Sync II / AMD FirePro S400
  - 软件：WGL_NV_swap_group / GLX_NV_swap_group / DX12 IDXGISwapChain::Present 联动

  5. 视景通道几何同步（Channel Alignment）

  - 每通道有独立的 view frustum（航向角、俯仰、FOV、非对称投影）
  - 边缘融合 Edge Blending、几何校正 Warping（球幕/柱幕）
  - 主眼点（eyepoint）统一，防止视差错位

  6. 监控与故障恢复

  - 心跳、丢包统计、帧延迟统计
  - 掉线通道自动 rejoin、状态快照重传
  - 教官台可视化每通道同步质量

  二、你的方案（时间戳 + 帧号下发）评估

  能解决的部分：仿真逻辑层的帧一致性 —— 每个客户端知道"现在该渲染第 N 帧、对应仿真时间 T"。

  不能解决的：
  1. 显示层撕裂：三通道投影会出现"左屏刚画完新帧，右屏还在旧帧"的错位 —— 必须 Genlock/Framelock
  2. 网络抖动下的等待策略：慢客户端怎么办？主机等 or 丢帧？需要明确策略
  3. 渲染耗时不一致：即使收到同一帧号，GPU 渲染时长不同，Present 时刻仍会错开
  4. 首帧对齐/热插拔：新加入通道如何快速追上
  5. 输入延迟：飞行员操纵杆输入到画面反映的端到端延迟约束（军标常要 <120ms）

  结论：时间戳+帧号是必要不充分条件。真正的"渲染同步"= 逻辑同步（软件） + Genlock/Framelock（硬件）。

  三、业内成熟方案

  标准/协议

  - CIGI (Common Image Generator Interface) — Boeing 主导，Host↔IG 通信事实标准
  - HLA (High Level Architecture, IEEE 1516) — 大型分布式仿真联邦
  - DIS (IEEE 1278) — 早期军用分布式仿真
  - PTP (IEEE 1588) — 精确时钟同步

  商业 IG / 视景引擎

  - Presagis Vega Prime —— 多通道 IG，含 Channel Sync
  - VT MÄK VR-Vantage / VR-Forces
  - CAE Medallion-6000（民航全动模拟机主流）
  - RSI (Rockwell Collins) EP-8000
  - Diamond Visionics GenesisRT

  游戏/图形引擎的多屏方案（可借鉴）

  - NVIDIA Mosaic + Quadro Sync II（多屏拼接 + 硬件 Framelock）
  - Unreal Engine nDisplay（Epic，原用于虚拟制片 LED 墙，已被大量视景项目采用）
  - Unity Cluster Rendering / ClusterDisplay
  - CryEngine / Unigine 都有 cluster render 模块
  - Equalizer / Collage（开源并行渲染框架）

  开源/学术

  - OpenSceneGraph + osgCluster
  - CaveLib / VR Juggler（早期 CAVE 环境）

  四、给你的落地建议（若从 0 到 1）

  1. 先分层：Time Sync → State Sync → Frame Sync → Display Sync，四层独立设计、独立测量
  2. 协议参考 CIGI，即使不完全兼容，消息设计思路成熟
  3. 硬件 Genlock 是硬指标：预算里必须留 Quadro Sync 卡，否则物理上做不到零撕裂
  4. 测量先于优化：加高精度探针（每帧记录 sim_time / recv_time / render_start / present_time），画瀑布图看错位来源
  5. 参考 nDisplay 的架构：它已经把 cluster sync + framelock + warp/blend 打通，可作为参照系
