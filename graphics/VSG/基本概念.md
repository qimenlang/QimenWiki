## Viewer 

VSG 的 `Viewer` 把 Vulkan 渲染拆成几个清晰阶段：

对应 Vulkan 原生 API：

- Record ≈ `vkBeginCommandBuffer` + 写入 draw/dispatch 命令 + `vkEndCommandBuffer`；在 CPU 上遍历场景图，把渲染指令写入 Vulkan Command Buffer。
- Submit ≈ `vkQueueSubmit`（把 Command Buffer 交给 GPU 队列执行）
- Present ≈ `vkQueuePresentKHR`（把渲染结果换链到屏幕）

#### Record 的是什么？

Record = 在 CPU 上遍历场景图，把渲染指令写入 Vulkan Command Buffer。

具体流程：

1. `CommandGraph::record()` 分配/重置一个 `VkCommandBuffer`
2. 调用 `RecordTraversal` 遍历场景图（RenderGraph → View → 几何体等）
3. 遍历时发出 Vulkan 命令

可以把它理解成：把场景图「编译」成 GPU 可执行的命令列表，这一步在 CPU 上完成，GPU 还没开始干活。

Record 的内容包括：

- 渲染 pass 的开始/结束
- 管线、descriptor、vertex buffer 绑定
- draw call
- compute dispatch
- barrier、copy 等

#### Submit 的是什么？

Submit = 把 Record 好的 Command Buffer 提交给 Vulkan 队列（Queue），让 GPU 异步执行。

Submit 时还会处理同步：

- Wait：等 swapchain 图像可用（`imageAvailableSemaphore`）、等数据传输完成
- Signal：渲染完成后发出 `renderFinishedSemaphore`，供 Present 等待

Submit 之后 GPU 在后台执行这些命令，CPU 可以继续做下一帧的 update/record。

------

#### Present 是什么？

`Viewer::present()` 调用各 `Presentation::present()`，本质是 `vkQueuePresentKHR`，把 swapchain 图像显示到屏幕：

Present 会等待 `renderFinishedSemaphore`，确保 GPU 渲染完成后再显示。

## CommandGraph

###### 是场景树顶层的命令缓冲录制根节点，每帧 `record()` 时它会：

1. 分配/重置一个 `VkCommandBuffer`（Primary 或 Secondary）
2. `vkBeginCommandBuffer`
3. 用 `RecordTraversal` 遍历子树，写入 GPU 命令
4. `vkEndCommandBuffer`
5. 把 CommandBuffer 加入 `RecordedCommandBuffers`，供 Submit 使用

###### **与场景是父子包含关系**

​	场景是被渲染的内容，CommandGraph 是**渲染管线/提交包装器**，在最顶层；

```txt
CommandGraph          ← Record/Submit 单位（1 个 VkCommandBuffer）
└── RenderGraph         ← 1 次 RenderPass（Begin/End）
    └── View            ← Camera + 场景 的配对
        ├── Headlight   ← 可选
        └── scenegraph  ← 你的场景内容（Group/Transform/Geometry...）
```

## RenderGraph

`RenderGraph` 专门封装 RenderPass 边界

Record 时在子树遍历前后插入 RenderPass 命令

一个 CommandGraph 可以包含多个 RenderGraph。
