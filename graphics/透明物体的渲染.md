### 前向渲染管线中透明物体的渲染

​	在前向渲染管线中，首先绘制非透明物体，然后对透明物体进行由远及近的排序，排序时使用的是透明物的中心点；如果遇到透明物体以莫比乌斯环形式相互遮挡，则此时透明物体的叠加渲染效果会不正确，这种不正确就不管了；

​	前向渲染天然适合透明,**这是透明数学上唯一正确的位置**

```glsl
for each fragment:
    compute lighting
    blend result
```

# 雾效与透明物体渲染方案

### 方案 2：新增transparent Pass,透明物体不写入fog depth

#### 核心思想（非常关键）

> **雾只看“第一个不透明表面”的距离**

#### 做法

在 Geometry Pass：

- Opaque：

  - 写：
    - Color
    - Depth
    - FogDepth（= view-space Z 或 linear depth）

- Transparent：

  - 不写 FogDepth，只参与颜色混合

  - 方案：新增transparent Pass，对透明draw call 禁用 AlphaRT 的 draw buffer

    - 这是你唯一能做到“真正不影响 AlphaRT”的方式。
    - 做法（CPU 端）：

    ```
    // Opaque pass
    GLenum bufsOpaque[] = {
        GL_COLOR_ATTACHMENT0, // albedo
        GL_COLOR_ATTACHMENT1, // alphaRT
    };
    glDrawBuffers(2, bufsOpaque);
    
    // Transparent pass
    GLenum bufsTrans[] = {
        GL_COLOR_ATTACHMENT0 // 只写 albedo
    };
    glDrawBuffers(1, bufsTrans);
    ```

    效果

    - 透明 fragment：
      - **根本不会触碰 AlphaRT**
    - AlphaRT：
      - 保持 opaque pass 写入的内容

在 Fog Pass：

```
fogAlpha = f(FogDepth)
finalColor = lerp(color, fogColor, fogAlpha)
```

#### 效果

- 不透明物体：
  - 雾稳定
- 透明物体：
  - 不再“改变”雾厚度
-  **“是否被透明混合导致雾差异巨大”问题 → 消失**

#### 成本

- +1 RT
- 极低逻辑复杂度
- 不需要改透明混合策略

👉 **这是我在你这个前提下最推荐的方案**



### 方案 3（进阶、但仍可控）：

### **雾效分两次：Opaque Fog + Transparent Fog**

#### 思想

把雾拆成：

1. **背景雾（不透明）**
2. **透明物体自身的雾**

#### Pipeline

```
1. Geometry Pass (Opaque only)
2. Fog Pass #1 (Opaque Fog)
3. Transparent Pass (alpha blend over fogged background)
4. 可选：Transparent Fog（近似）
```

#### 好处

- 背景雾是对的
- 透明不会“污染”背景雾

#### 坏处

- 透明物体“没那么雾”
- 但比现在强很多

👉 这是**很多游戏的真实做法**
