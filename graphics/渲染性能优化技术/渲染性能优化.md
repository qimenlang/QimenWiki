## 渲染性能优化

#### 减少Draw Call

​	原理：Draw Call是CPU向GPU发送的绘制命令，每次调用都涉及以下开销：

- CPU状态准备（缓冲区VBO、IBO绑定、材质绑定、着色器切换）

- GPU命令队列提交
- 驱动层开销

​	减少Draw Call的核心原理是合并多个绘制操作，减少CPU-GPU通信次数

1. 合批

   - 静态合批：
     - 将使用相同材质的网格合并为一个大网格，合并后的网格存储为统一的顶点、索引缓冲；
     - 渲染时，只调用一次DrawElement;
     - 适用于静态物体；
     - 代价：
       - 内存开销可能暴涨：n个相同的小网格，如果独立渲染，内存只占用一个网格模型，合并到大网格中，会复制n份网格；
       - 不可动态修改：动态变化后需要重新烘焙；
       - 对不可见物体进行静态合批：将本来分布范围很广的物体设置为静态合批之后，只要静态合批之后的大mesh有一部分不被视锥体剔除或遮挡剔除，就会继续渲染整个Mesh，片段着色器全部运行；
     - 静态合批组中的物体被移动后，静态合批的顶点、索引缓冲区不变，被移动的物体的索引失效，被移动的物体单独重新渲染，分裂为两次draw call;
     - 应用：静态场景建筑、地形装饰
     - 最佳实践：只对那些数量多、使用相同材质、并且确实对Draw Call造成压力的静态物体使用静态合批
     
   - 动态合批：
     - 运行时，合并使用相同材质的网格，**每帧**将 **所有顶点转换到同一空间（世界空间）** 后拼接为连续的顶点、索引缓冲区；
     - 渲染时，受限于每批顶点上限，可能多次draw call；
     - 合并条件：
       - 物体材质相同（纹理、shader参数）
       - 单个物体顶点数较少
       - **物体必须使用同一缩放**：
         - 不使用统一缩放会导致法线向量破坏：法线需使用 **逆转置矩阵（Inverse Transpose Matrix）** 变换：`normal_world = (M^{-1})^T * normal_local`，逆转置矩阵无法合并计算，每个物体需要单独计算；
     - 优势：支持物体动态位置变化，没有额外内存开销
     - 代价：
       - 每帧重组顶点数据，CPU计算量增加
       - 条件严苛：材质必须完全相同，顶点数严格限制
     - 应用：简单粒子、低模草丛

2. 纹理图集

#### MIPMAP

1. 预处理生成纹理链

2. 渲染时根据屏幕像素与纹理像素的比例，动态选择对应的mipmap层级进行采样

3. 解决的问题

   | 问题               | Mipmap解决方案          | 效果             |
   | :----------------- | :---------------------- | :--------------- |
   | 摩尔纹（Aliasing） | 避免远距离过采样        | 消除闪烁和锯齿   |

#### LOD(Level of details) : 几何复杂度的动态降级

1. 原理：根据距离相机距离（远距离、scale放大时不对），或者物体在屏幕像素占比，动态切换低模高模；

   - 计算屏幕像素占比：屏幕占比 = 物体投影高度/屏幕高度
     - 获取物体包围盒 （因使用包围盒，导致实际屏幕占比会有约10%误差）
     - 使用View矩阵&Projection矩阵投影到裁剪空间
     - 计算投影高度，转换到屏幕空间，计算占比

2. 时机：在提交Draw Call前的CPU准备阶段，CPU根据**物体到相机的距离**或**屏幕空间占比**计算LOD级别，选择对应精度的模型，绑定选定的模型到VB、IB；

3. GPU Driven LOD

   - 将LOD决策逻辑移动到GPU Computer Shader中进行
   - GPU Shader **视锥剔除+遮挡剔除+LOD决策** ：**单次Compute Shader Pass完成可见性判定 + LOD决策**，彻底解放CPU

   ```mermaid
   graph TB
       A[场景数据] --> B(Compute Shader)
       B --> C{并行处理每个实例}
       C --> D[视锥剔除]
       C --> E[遮挡剔除]
       C --> F[LOD决策]
       D & E --> G[可见性标记]
       F --> H[LOD级别存储]
       G & H --> I[间接渲染参数]
       I --> J[GPU渲染管线]
   ```

#### 遮挡剔除

1. 原理：遮挡物的包围盒写入到深度图，对被遮挡物的**包围盒进行深度测试**，返回深度测试通过的像素数，如果像素数为0，则完全被遮挡，否则需要渲染被遮挡物；
2. 软件光栅化： 在CPU上使用软件光栅化来生成一个简化的深度缓冲（通常称为深度金字塔或Hi-Z），然后利用这个深度缓冲来测试物体包围盒的可见性；
3. 硬件遮挡查询：使用GPU查询一个物体的包围盒在深度缓冲中的可见性；
4. 基于层次的遮挡剔除
   - BVH （Bounding Volume Hierarchical ）
