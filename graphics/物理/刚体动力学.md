好的，我们来深入且详细地讲解物理引擎（以 **NVIDIA PhysX** 为例）中的**刚体动力学**。

刚体动力学是物理引擎最核心的部分，它模拟的是在受力作用下、**形状和大小都不会改变**的理想刚体的运动。简单来说，它回答了这个问题：“这个物体受到各种力和碰撞后，下一刻它会在哪里？会以什么姿态运动？”

---

### 一、 刚体的核心属性

在 PhysX 中，一个刚体（`PxRigidDynamic`）不仅仅是一个渲染模型，它是一个包含了大量物理属性的数据集合：

1.  **变换 (Transform)**
    *   **位置 (Position)**: 一个三维向量 `(x, y, z)`，表示刚体在世界空间中的位置。
    *   **旋转 (Rotation)**: 通常用**四元数 (Quaternion)** 表示，相比欧拉角能避免万向节死锁且插值更平滑。它定义了刚体的朝向。

2.  **运动学状态 (Kinematic State)**
    *   **线速度 (Linear Velocity)**: 一个三维向量，表示刚体每秒钟在 x, y, z 方向上的移动速度（米/秒）。`velocity = (dx, dy, dz)`。
    *   **角速度 (Angular Velocity)**: 一个三维向量，表示刚体每秒钟绕其本地坐标轴的旋转速度（弧度/秒）。向量的方向代表旋转轴，长度代表旋转的快慢。

3.  **质量属性 (Mass Properties)**
    *   **质量 (Mass)**: 标量，单位通常是千克 (kg)。决定了物体惯性的大小。
    *   **质心 (Center of Mass)**: 一个三维向量，表示物体质量的中心点。力的作用点会影响运动。
    *   **惯性张量 (Inertia Tensor)**: 一个 3x3 的矩阵，描述了物体绕不同轴旋转的难易程度。它决定了角加速度与扭矩之间的关系。一个细长的杆绕其长度方向旋转很容易（惯性小），绕垂直方向旋转则很难（惯性大）。PhysX 通常可以根据物体的形状自动计算。

4.  **物理材质 (Physical Material)**
    *   **动态摩擦力 (Dynamic Friction)**: 物体在表面上**滑动时**的摩擦力系数。
    *   **静摩擦力 (Static Friction)**: 物体在表面上**静止时**，使其开始运动所需克服的摩擦力系数。通常大于动态摩擦。
    *   **恢复系数 (Restitution)**: 弹性系数，取值范围 [0, 1]。0 表示完全非弹性碰撞（如粘土落地），1 表示完全弹性碰撞（理想小球完美反弹）。

---

### 二、 刚体的类型

在 PhysX 中，刚体主要分为两种，它们的运动方式有根本区别：

1.  **静态刚体 (Static Rigidbody) - `PxRigidStatic`**
    *   **特点**：质量无限大，永远静止不动。参与碰撞检测，但自身永远不会被撞动。
    *   **用途**：地板、墙壁、大型固定障碍物等场景几何体。
2.  **动态刚体 (Dynamic Rigidbody) - `PxRigidDynamic`**
    *   **特点**：完全由物理引擎控制。引擎会根据它受到的力、碰撞和约束来计算它的运动。
    *   **用途**：游戏中的可互动物品（箱子、球）、角色（通常通过角色控制器间接控制）、机器人连杆等。

3.  **Trigger**

4.  **运动学刚体 (Kinematic Rigidbody) - `PxRigidDynamic` 设置为 Kinematic**
    *   **特点**：不受物理引擎力的影响。它的运动完全由开发者通过代码**直接设置其位置 (`setGlobalPose`)** 来控制。
    *   **工作原理**：物理引擎会检测运动学刚体与其他刚体的碰撞，并**“推开”** 那些被它撞到的动态刚体，但它自身的运动路径不会被力或碰撞改变。
    *   **用途**：电梯、移动的平台、由动画驱动的物体、或者在某些情况下用于高级角色控制。它是在物理世界中“开辟道路”的物体。

### 三、 刚体动力学的仿真流程（核心循环）

物理引擎的核心是一个**离散的、逐步推进的仿真循环**，通常以固定的时间步长（如 1/60秒）进行，以保证仿真的稳定性。这个过程在 PhysX 中由 `scene->simulate(deltaTime)` 触发。

#### 步骤 1: 应用力 (Apply Forces)
在仿真步开始前，开发者或游戏逻辑可以对刚体施加各种力。
*   **力 (Force)**：`addForce(...)`。例如重力 (`PxScene` 全局设置)、推力、风力。力会产生**线加速度** (`a = F / m`)。
*   **扭矩 (Torque)**：`addTorque(...)`。扭矩是旋转的力，会产生**角加速度**。
*   **脉冲 (Impulse)**：`addImpulse(...)`。脉冲是瞬间的力冲量 (`J = F * t`)，会立即改变速度。例如子弹射击、爆炸冲击、跳跃。

#### 步骤 2: 碰撞检测 (Collision Detection) - 宽相位 & 窄相位
物理引擎检查所有刚体之间是否发生碰撞。
*   **宽相位 (Broadphase)**：快速找出**可能**发生碰撞的物体对。通常使用空间数据结构（如 bounding volume hierarchy - BVH）来快速剔除明显不碰撞的物体，极大提升效率。

* **窄相位 (Narrowphase)**：对宽相位筛选出的物体对进行**精确的几何相交测试**。计算碰撞点、碰撞法线、穿透深度。

  *   射线检测
      *   射线与BVH进行宽相位过滤
      *   射线与包围盒：分别计算射线与三个坐标轴垂直的三对平面的交点；
      *   射线与三角形平面：首先计算射线与三角形所在平面的交点，然后判断该交点是否在三角形内部（通常使用**重心坐标 Barycentric Coordinates** 法；

  *   几何相交测试（Shape & Shape）
      *   **分离轴定理 (Separating Axis Theorem - SAT)**: 用于**凸形状**（如盒子、凸包）之间测试的强大数学工具。如果能找到一个轴，使得两个形状在该轴上的投影是分离的，则它们一定没有碰撞。
          *   凸包：任何一个表面进行无限扩展，无法与其他表面相交的物体；
      *   **Gilbert–Johnson–Keerthi (GJK) 算法**: 用于计算两个凸形状之间的距离和最近点。非常高效，是现代物理引擎的标配。它可以判断是否相交（如果距离<=0则相交）。
      *   **Expanding Polytope Algorithm (EPA)**: 如果GJK检测到碰撞，EPA算法则用于计算碰撞的**穿透深度**和**接触法线**。

*   碰撞过滤：碰撞层（Collision Layers）和碰撞矩阵（Collision Matrix）

    这是实现碰撞过滤最常用、最有效的方法。它模拟了一个**二维矩阵，**定义了不同分组之间是否进行碰撞。

    1. **碰撞层 (Layer)**：
       - 定义一个枚举，每个值代表一个逻辑分组，例如：`Player`, `Enemy`, `PlayerBullet`, `EnemyBullet`, `Wall`, `Ground`, `Trigger`, `Debris`等。
       - 每个碰撞体（Collider）都会分配到一个特定的层中（例如，玩家的碰撞体在`Player`层，敌人的碰撞体在`Enemy`层）。
    2. **碰撞矩阵 (Matrix)**：
       - 这是一个二维表，行和列都是所有定义的层。
       - 矩阵中的每个单元格是一个布尔值，表示 **“行层”** 中的物体是否与 **“列层”** 中的物体进行碰撞检测。
       - **例如**：
         - `Player` vs `Enemy` = `True` (玩家和敌人需要碰撞)
         - `Player` vs `PlayerBullet` = `False` (玩家不会被自己的子弹击中)
         - `Enemy` vs `EnemyBullet` = `False` (敌人不会被自己的子弹击中)
         - `PlayerBullet` vs `EnemyBullet` = `False` (子弹之间不碰撞，节省性能)
         - 所有物体 vs `Wall`/`Ground` = `True` (所有物体都与墙壁和地面碰撞)

#### 步骤 3: 求解约束 (Solving Constraints)
这是最复杂的部分。引擎需要解决所有“约束”，包括：
*   **接触约束 (Contact Constraints)**：由碰撞产生。约束是“两个物体不能相互穿透”。求解器会计算出一个**接触力**（或冲量），将两个物体推开。
*   **关节约束 (Joint Constraints)**：如铰链、滑块，限制了刚体之间的相对运动。
PhysX 使用一个**迭代求解器 (Iterative Solver)**，多次迭代来找到一个近似解，以满足所有约束。迭代次数越多，精度越高，但计算成本也越大。

#### 步骤 4: 积分 (Integration)
这是最后一步，根据上一步计算出的合力和速度，更新刚体的运动状态。
*   **使用积分方法（如 Semi-Implicit Euler）**：
    *   更新速度：`新速度 = 当前速度 + (加速度 * 时间步长)`
    *   更新位置：`新位置 = 当前位置 + (新速度 * 时间步长)`
    *   同样地，也会更新角速度和旋转。

#### 步骤 5: 获取结果 (Fetch Results)
仿真步结束后，调用 `scene->fetchResults(true)`。这一步将计算好的新位置、新速度等数据从物理引擎的内部缓冲区中提取出来，使其对游戏逻辑或渲染循环可用。渲染引擎随后根据新的变换数据来绘制物体。

### 四、 在代码中的直观体现（以PhysX为例）

```cpp
// 1. 创建动态刚体
PxRigidDynamic* dynamicBox = PxCreateDynamic(*gPhysics, 
    PxTransform(PxVec3(0.f, 10.f, 0.f)), // 初始位置（离地10米）
    PxBoxGeometry(1.f, 1.f, 1.f),        // 形状（1x1x1的盒子）
    *gMaterial,                          // 物理材质
    10.0f);                              // 密度（或直接设置质量）

// 2. 设置属性（可选）
dynamicBox->setLinearDamping(0.5f);      // 设置线性阻尼（类似空气阻力）
dynamicBox->setAngularDamping(0.6f);     // 设置旋转阻尼

// 3. 将刚体添加到场景中
gScene->addActor(*dynamicBox);

// --- 在主游戏循环中 ---
while (1) {
    // 4. 施加力（例如：在每个仿真步都施加的重力由场景全局设置，这里我们施加一个向右的力）
    dynamicBox->addForce(PxVec3(100.f, 0.f, 0.f), PxForceMode::eFORCE);

    // 5. 推进物理仿真（固定时间步长，例如1/60秒）
    gScene->simulate(1.f/60.f);
    gScene->fetchResults(true);

    // 6. 从刚体中获取更新后的位置和旋转，传递给图形渲染
    PxTransform newTransform = dynamicBox->getGlobalPose();
    // myRenderMesh->setPosition(newTransform.p);
    // myRenderMesh->setRotation(newTransform.q);
}
```
**结果**：这个盒子会受到向下的重力和持续的向右的推力，它会一边下落一边向右加速运动，如果碰到地面或其他物体，还会发生碰撞和反弹。

### 总结

PhysX 的刚体动力学是一个由**力**和**约束**驱动、通过**积分**来更新状态的精细过程。它通过**碰撞检测**来感知世界，通过**约束求解**来与世界交互，最终通过**积分**来决定自己下一刻的命运。理解这个流程对于在机器人仿真中创建逼真的行为、调试奇怪的物理bug（如物体抖动、飞走）以及进行高级定制（如自定义关节、力场）都至关重要。
